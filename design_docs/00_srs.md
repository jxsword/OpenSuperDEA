## 1. 引言

### 1.1 目的

本文档完整定义 OpenSuperDEA（用 C++ 全量实现 MaxDEA X 功能的开源项目）的软件需求：功能需求、非功能需求、外部接口、未来扩展与验收标准。作为 M1-M8 全部里程碑的需求基线，用于：①开发前的设计与实现依据；②每里程碑阶段门禁的验收准绳；③测试用例与需求的双向追溯。

### 1.2 范围

- **覆盖**：CLI 形态全功能（数据 IO、命令行、径向/非径向/方向距离/成本收益/FDH/乘子/交叉效率/窗口/TFP 常规模型族，MinDS/FDEF/弱前沿/AR/Cone/Nash/Cluster/EBM/修正 SBM/HMB/Malmquist 7 参比 10 项独有算法，10 万/100 万 DMU 性能能力）、GUI 形态（M6，Qt6）、平台扩展（M7）与发布工程（M8）。
- **不覆盖**：模糊 DEA、Robust/order-m、SFA、bootstrap 统计推断（MaxDEA X 本身不含，开源生态独有扩展，见第 7 章扩展清单）；InverseDEA 等配套软件。
- **里程碑边界**：M1 仅工程底座（无任何算法实现）；首个算法验收自 M2 始。

### 1.3 读者对象

- 开发智能体（Zcode）：实现与自测依据；
- 用户（项目所有者）：需求裁决、里程碑验收；
- 后续协作者：理解功能边界与验收标准。

### 1.4 术语定义

| 术语 | 定义 |
|---|---|
| DEA | 数据包络分析（Data Envelopment Analysis），非参数前沿效率评价方法 |
| DMU | 决策单元（Decision Making Unit），效率评价对象 |
| PPS | 生产可能集（Production Possibility Set） |
| 前沿 | 投入产出空间中由最优 DMU 构成的效率边界 |
| CRS/VRS/NIRS/NDRS | 规模报酬假设：不变/可变/非递增/非递减 |
| 定向（orientation） | 投入导向（in）/ 产出导向（out）/ 非导向（non） |
| CCR/BCC | 径向模型（Charnes-Cooper-Rhodes 1978 / Banker-Charnes-Cooper 1984） |
| SBM | 基于松弛的测度（Slacks-Based Measure，Tone 2001） |
| ERM | 增强 Russell 测度（Enhanced Russell Measure），与 SBM 并列的最大距离度量 |
| EBM | 基于 ε 的混合距离测度（Epsilon-Based Measure，Tone-Tsutsui 2010） |
| DDF/RDM | 方向距离函数 / 范围调整方向测度（Range-Directional Measure） |
| FDH | 自由处置包络（Free Disposal Hull） |
| MinDS | 最小距离强有效前沿（Closest Target），强单调 |
| FDEF | 全维有效面（Full Dimensional Efficient Facet） |
| 弱有效前沿 | 仅满足弱 Pareto 有效的边界（含松弛不为零的投影） |
| AR/Cone | Assurance Region / 锥比（Cone Ratio）受限乘数模型 |
| Nash 博弈交叉效率 | Liang et al. 2008 博弈论交叉效率（Nash 均衡求解） |
| Cluster 8 基准 | 8 种参比组合的群组基准模型（Seiford-Zhu 2003 context-dependent DEA） |
| Malmquist/HMB | 全要素生产率（TFP）指数：Malmquist 与 Hicks-Moorsteen |
| 对拍（parity test） | 与开源实现（deaR/DEAPack/PyDEA/R productivity）数值比对验证 |
| 黄金算例 | 论文发表的标准算例（含数据与全部期望结果），用于 L2 复现 |
| LP/MILP | 线性规划 / 混合整数线性规划 |
| big-M | MILP 中将非线性约束线性化的大常数，需自动估计保证数值稳定 |
| 强单调 | 目标改进必然使效率测度严格改进的数学性质 |
| L1-L4 | 四层验证体系：开源对拍/论文算例/数学性质/性能基准 |
| P0-P3 | 优先级：必须/重要/一般/可选 |
| 里程碑 M1-M8 | M1 工程底座、M2 常规引擎、M3 性能 10 万、M4 极速 100 万、M5 独有算法、M6 GUI、M7 平台、M8 发布 |

## 2. 总体描述

### 2.1 产品愿景

为 DEA 研究者提供**功能对齐 MaxDEA X、性能对标官方基准、完全开源可复现**的效率测算工具：CLI 全功能脚本化（M1-M5）、GUI 低门槛操作（M6）；独有算法（MinDS/FDEF/博弈交叉效率等 10 项）与百万级 DMU 极速求解是核心差异化价值。

### 2.2 用户特征

| 用户 | 特征 | 主要场景 |
|---|---|---|
| DEA 研究者/研究生 | 熟悉模型理论，需论文可复现数值 | 论文算例复现、面板数据 TFP 测算、Cluster 分层分析 |
| 数据分析师 | 熟悉脚本/管道，批量处理 | CSV 数据批量测算、结果导出接入下游分析 |
| GUI 用户（M6） | 习惯 MaxDEA 式图形操作 | 数据导入→模型配置→结果表/图形输出 |

### 2.3 运行环境

- **开发与运行（一期）**：WSL Ubuntu（ubuntu2604，GCC 16），Ubuntu 24.04+ 兼容；
- **Windows（CI 一期，原生 M7）**：GitHub Actions windows-latest（MSVC）；
- **构建**：CMake ≥ 3.16 + vcpkg manifest；离线本地运行，无网络依赖；
- **对拍验证环境**：本机 R（deaR、productivity）与 Python（DEAPack、PyDEA）环境，经外部进程调用。

### 2.5 假设与依赖

- 依赖 vcpkg 官方端口提供 eigen3/highs/cli11/gtest/qhull 的可复现构建（含 Windows 交叉编译场景）；
- 假设 GitHub Actions 提供的 Linux/Windows runner 规格满足 CI 时长要求（HiGHS 首次编译走 vcpkg 缓存）；
- 对拍工具（deaR/DEAPack/PyDEA/productivity）版本以开发机安装版为准，升级需回归对拍；
- 8 条实现假设（A-001~A-008）见 00a 拆解清单 §5.2，其中影响范围条款已写入对应 FR。

## 3. 功能需求

> **字段约定**：每个 FR 以三级标题给出需求编号与功能名称，表格含 10 字段行；为避免模板化重复，字段按三级绑定：①章级公共默认值（下）→ ②模块公共字段默认值（各模块开头）→ ③FR 条目单列字段（优先）。FR 未单列字段按此顺序取最近的绑定值，字段仍然齐全、绑定关系显式可追溯。
>
> **章级公共默认值（全章适用，模块/FR 可覆写）**：触发条件=用户执行对应子命令；输入=已校验数据集 + 模型参数（FR-IO/FR-CLI 产出）；处理逻辑=按模型数学形式构造 LP/MILP → HiGHS 求解 → 结果组装（模型特有步骤以各 FR 功能描述/单列处理逻辑为准）；输出=标准结果对象（效率值/投影/参考集 λ/slack/乘子，经 FR-OUT 导出）；异常处理=求解不可行/无界/超时→EXIT_SOLVE；前置条件=数据集已载入且参数组合合法（FR-CLI-008）；后置条件=结果对象生成待导出。

### 3.2 模块：数据 IO（FR-IO）

**模块公共字段默认值**：触发条件=用户以 CSV 文件路径调用 CLI；前置条件=文件存在且可读；后置条件=数据集对象就绪（供引擎消费）；异常处理=按错误分类返回 EXIT_DATA 并输出「文件:行号:原因:修复提示」。
