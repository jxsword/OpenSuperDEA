# SRS 多轮审核记录（00b 配套，阶段一产出物）

> 对象：design_docs/00_srs.md ｜ 记录时间：2026-10-24 ｜ 审核人：开发智能体（Zcode）
> 依据：software-requirements-engineer 技能 review-checklist.md（完整性 → 一致性 → 可执行性）

## 工具链说明

- 技能自带 `srs_audit.py` 仅接受 docx 输入（python-docx 管线），与本项目的「Markdown 落库」决策（DR-005）不兼容，故不适用。
- 替代门禁：自建脚本 `tmp/srs_field_check.py`（过程文件，不入库）——检查每个 FR 的 10 字段存在性（FR 行 > 模块默认 > 章级默认三级绑定）、FR 编号格式与唯一性、模块级计数；辅以模糊词扫描（可能/大概/尽量）与人工清单核对。
- **格式决策**：116 条 FR 若每条展开 12 字段将产生大量模板化重复，故采用「章级公共默认值 → 模块默认值 → FR 单列字段」三级绑定，字段仍全部在案、绑定显式。此为文档格式决策，不影响需求语义。

## 第 2 轮：一致性审核（V0.2 → V0.3）

检查项：需求间矛盾、术语一致性、编号连续性、计数对齐、优先级口径。

| # | 发现 | 处置 |
|---|---|---|
| 1 | FR-CLU-006/007 与 FR-TFP-005/006 合并写在单标题下，编号声明与条目数不符（114 标题 vs 116 编号） | 拆分为 4 个独立 FR 条目，各自含完整字段 |
| 2 | 「同径向族」引用式模块默认值无法自证字段覆盖（NRAD/DDF） | 改为「取章级公共默认值 + 模块特有补充」自足表述 |
| 3 | 模块默认值与章级默认值的绑定顺序未显式化 | 字段约定改为三级绑定（章 → 模块 → FR 单列优先） |
| 4 | FR/FR 计数：00a 写 117，实际 116（RAD 窗口移出 −1，CLU-012 新增 +1）；NFR 实际 21 非初稿声明的 16 | 00a 与 SRS 变更历史计数全部对齐（FR 116 / NFR 21） |
| 5 | 独有算法优先级在 README（P0/P1 并列）与调研表之间口径不一 | SRS 按 M0 §3.2 结论取单值（Nash/HMB/AR=P0，MinDS/Malmquist-7/EBM/FDEF/WEF/Cluster/mSBM=P1），并保留调研表 P0/P1 原文可追溯 |
| 6 | 术语「benchmarking」与「参比」混用风险 | 术语表统一：参比（reference set combination），8 基准名称保留英文原名 |
